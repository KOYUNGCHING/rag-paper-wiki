LLM 為什麼需要外部知識？

只靠模型權重（parametric memory）

  • 知識藏在權重裡，難以直接修改、檢查，也不會告訴你來源。
  • 想把知識都塞進去，就需要很大的模型，訓練與查詢都貴。

加上外部文字記憶（non-parametric memory）

  • 知識放在可讀的文字資料庫，可以檢查、擴充或替換。
  • 回答時先去查，再根據查到的內容生成。

但是：外部資料本身也可能有錯或有偏見（RAG 論文 Broader Impact）。

RAG 的三步驟

  • Retrieve：retriever 從資料庫找出最相關的 k 段文字（chunks）。
  • Augment：把 chunks 接在問題後面，變成 generator 的 context。
  • Generate：generator 根據問題與 context 寫出答案，不只是擷取原文片段。

原始 RAG 論文是特定架構（DPR retriever + BART generator）；今天說的「RAG」常泛指這種 retrieval + generation 流程（整理）。

DPR：怎麼找到相關的 chunks？

  • BM25 靠關鍵字比對；dense retrieval 把文字變成向量，字面不同但語意相近也能找到。
  • DPR 用兩個 encoder 分別把問題、passage 變成向量，以內積排序；passage 向量事先建好索引。
  • Top-k accuracy：前 k 個結果中，至少一個含答案的問題比例。

DPR 不是在每個資料集都贏：SQuAD 上 BM25 較高。

互動範例：一次完整的 RAG 虛構範例

  1. 1 Question

    「青嶼市的捷運何時通車？哪一條線最先開？」

    青嶼市是虛構城市，以下資料全部是教學用假資料。

  2. 2 Retrieve：從 5 個 chunks 取 top-3

    Chunk內容分數（示意）
    K1青嶼市捷運於 2015 年通車，首條營運路線為藍線。0.91
    K3藍線連接青嶼車站與港區，全長 12 公里。0.74
    K2青嶼市捷運原計畫 2012 年完工，因工程延誤延後通車。0.70
    K4綠線於 2019 年加入營運。0.41
    K5青嶼市公車路網於 1998 年重整。0.22

  3. 3 Augment：組成 prompt

    請根據以下資料回答問題。
[K1] 青嶼市捷運於 2015 年通車，首條營運路線為藍線。
[K3] 藍線連接青嶼車站與港區，全長 12 公里。
[K2] 青嶼市捷運原計畫 2012 年完工，因工程延誤延後通車。
問題：青嶼市的捷運何時通車？哪一條線最先開？

  4. 4 Generate：有來源的答案

    青嶼市捷運在 2015 年通車[K1]，最先營運的是 藍線[K1]。

    每一句都能回指到 chunk：這就是「讓 LLM 先查資料再回答」。注意 K2 的「2012」是可能誤導的雜訊，下一張會用到。

原始 RAG：兩種記憶一起用

  • Retriever 由 DPR 初始化，generator 是 BART。
  • 微調時更新 query encoder 與 generator，文件索引保持不動。
  • 作者主張：換掉外部索引，就能改變模型回答的時效性事實，不必重訓 generator。
  • RAG-Sequence 整段答案用同一份文件；RAG-Token 每個 token 可以用不同文件。

FiD：一次融合很多 passages

  • 每組「問題＋passage」分別 encode，decoder 再一起看全部。
  • 分開 encode，計算量隨 passage 數線性成長。
  • FiD 不是新的 retriever：論文用 BM25 或 DPR 取得 passages。
  • FiD 的實驗中，passage 越多，Exact Match 越高（FiD Figure 3，顯示範圍內）。
  • 但原始 RAG 的 RAG-Token 在文件增加後反而下降（RAG Figure 3）。k 越大不一定越好。

Self-RAG：決定何時找，並檢查自己的回答

  • 每次都固定檢索，可能帶進不需要或離題的內容；找到相關資料，也不保證回答會忠於它。
  • 四種 reflection tokens：
    • Retrieve 要不要找
    • IsRel 相關嗎
    • IsSup 有證據支持嗎
    • IsUse 有用嗎
  • Tokens 是訓練出來的預測，推論時不需要另外的 critic。不等於可靠的內省。

ASQA 引用品質（Self-RAG Table 2）：Self-RAG 13B precision 70.3／recall 71.3；Ret-ChatGPT 65.1／76.6。
Precision 較高、recall 較低，不是全面勝出。

RAGChecker：用 claims 診斷錯誤

  • 把回答與標準答案拆成一句句 claims，逐一檢查是否被 chunks 支持。
  • Retriever 指標：claim recall、context precision。
  • Generator 指標：faithfulness、noise sensitivity、hallucination…
  • 可信度：與人類判斷的 Pearson（overall）61.93，人類之間是 70.09；但不是每一欄都勝過 baseline。

設計取捨：什麼時候不該多找？

更多 context

Claim recall 與 faithfulness 上升，但雜訊也變多（RAGChecker 作者觀察）。

檢索門檻

Self-RAG 提高 threshold、少檢索時，PubHealth 準確率變化小，PopQA 下降較多（Figure 3(c)）。

無法同時最佳化

Prompt 要求更忠實時，context utilization 上升，noise sensitivity 卻變差。

成本

Passage 很多時的效率仍是 FiD 作者列出的未解問題。

沒有一組「最佳 k」：要看任務、資料，以及你在意哪個指標（整理）。

小測驗

1. 回答漏了重要資訊，而且 claim recall 很低。最可能是哪個模組的問題？
看答案

Retriever。需要的資訊根本沒被找回來。

2. DPR 在所有資料集都比 BM25 好？
看答案

不是。SQuAD 的 Top-20 accuracy 是 BM25 較高（63.2 vs 68.8）。

3. Self-RAG 輸出 IsSup token，代表模型「確實知道」回答有證據支持？
看答案

不是。它是訓練出來的 token 預測，標註來自 GPT-4 蒸餾，仍需要外部評估。
